# Book API toy project in Go

A small REST API for managing books, written in Go with the [Gin](https://github.com/gin-gonic/gin) web framework and [GORM](https://gorm.io/) for the data layer.

Books are persisted in a PostgreSQL database, so data survives process restarts.

## Requirements

- Go 1.26.4 or later
- PostgreSQL 17 (a Docker image is provided under `docker/`)

## Database

The app connects to PostgreSQL using the `DATABASE_URL` environment variable. If it is unset, it falls back to:

```
host=localhost user=pguser password=pgpwd dbname=bookapi port=5432 sslmode=disable
```

A Docker image based on `postgres:17.5` is provided in `docker/`. It seeds the schema from `docker/init.sql`, which creates the `books` and `comments` tables along with the `books_id_sequence` and `comments_id_sequence` sequences used to auto-generate IDs. The `comments` table references `books(id)` with `ON DELETE CASCADE`, so deleting a book removes its comments.

```bash
# Build the database image
docker build -t bookapi-db ./docker

# Run it (exposes PostgreSQL on :5432)
docker run --name bookapi-db -p 5432:5432 -d bookapi-db
```

The image sets `POSTGRES_USER=pguser`, `POSTGRES_PASSWORD=pgpwd`, and `POSTGRES_DB=bookapi`, matching the default `DATABASE_URL` above.

## Running

With the database running:

```bash
go run .
```

The server listens on `:8080`. Trusted proxies are disabled, so client IPs are taken from the connection rather than forwarding headers.

To build a binary instead:

```bash
go build -o bookapi .
./bookapi
```

Gin runs in debug mode by default; set `GIN_MODE=release` to quiet the startup warnings and request logging.

## API

All routes are served under the `/api/v1` prefix.

| Method   | Path                        | Description                  | Success response      |
| -------- | --------------------------- | ---------------------------- | --------------------- |
| `GET`    | `/api/v1/books`             | List all books               | `200` with JSON array |
| `GET`    | `/api/v1/books/:id`         | Fetch a single book by ID    | `200` with the book   |
| `POST`   | `/api/v1/books`             | Create a book                | `201` with the book   |
| `POST`   | `/api/v1/books/:id/comments` | Add a comment to a book     | `201` with the comment |
| `DELETE` | `/api/v1/books/:id`         | Delete a book by ID          | `204` with no body    |

### Book

```json
{
  "id": 1,
  "title": "The Go Programming Language",
  "author": "Donovan & Kernighan",
  "comments": ["A classic", "Great reference"]
}
```

`title` and `author` are stored by the database. `id` is generated by PostgreSQL from the `books_id_sequence` sequence; any value sent by the client is ignored. `comments` is exposed on the wire as a flat array of strings, even though each comment is persisted as its own row in the `comments` table.

### Comment

Comments are added via `POST /api/v1/books/:id/comments` with a body of:

```json
{
  "text": "A classic"
}
```

`text` is required. The response is the stored comment:

```json
{
  "id": 1,
  "book_id": 1,
  "text": "A classic"
}
```

### Errors

Errors are returned as `{"error": "..."}`:

- `400 Bad Request` — the `:id` path parameter is not a valid unsigned integer, or the request body is not valid JSON (e.g. a missing `text` when adding a comment).
- `404 Not Found` — no book exists with the given ID.
- `500 Internal Server Error` — a database/query error occurred.

## Examples

```bash
# Create a book
curl -X POST http://localhost:8080/api/v1/books \
  -H 'Content-Type: application/json' \
  -d '{"title":"The Go Programming Language","author":"Donovan & Kernighan"}'

# List all books
curl http://localhost:8080/api/v1/books

# Fetch one
curl http://localhost:8080/api/v1/books/1

# Add a comment to a book
curl -X POST http://localhost:8080/api/v1/books/1/comments \
  -H 'Content-Type: application/json' \
  -d '{"text":"A classic"}'

# Delete one
curl -X DELETE http://localhost:8080/api/v1/books/1
```

## Layout

```
main.go                  # server setup, DB connection, repository/handler wiring, listener on :8080
handlers/handlers.go     # HTTP handlers, BookStore interface, route registration
repository/repository.go # Book and Comment GORM models and BookRepository (Insert/Find/FindAll/AddComment/Delete)
docker/                  # PostgreSQL image (Dockerfile) and schema seed (init.sql)
```

## Testing

Unit tests use [testify](https://github.com/stretchr/testify). Repository tests run against an in-memory SQLite database, and handler tests use `httptest` with a mocked `BookStore`.

```bash
go test ./...
```

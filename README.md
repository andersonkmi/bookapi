# Book API toy project in Go

A small REST API for managing books, written in Go with the [Gin](https://github.com/gin-gonic/gin) web framework and [GORM](https://gorm.io/) for the data layer.

Books are persisted in a PostgreSQL database, so data survives process restarts.

## Requirements

- Go 1.26.4 or later
- PostgreSQL 17 (a Docker image is provided under `docker/`)

## Database

The app connects to PostgreSQL using the `DATABASE_URL` environment variable. If it is unset, it falls back to:

```
host=localhost user=pguser password=pgpwd dbname=bookapi port=5432 sslmode=disable
```

A Docker image based on `postgres:17.5` is provided in `docker/`. It seeds the schema from `docker/init.sql`, which creates the `books` and `comments` tables along with the `books_id_sequence` and `comments_id_sequence` sequences used to auto-generate IDs. `books.title` carries a `UNIQUE` constraint, and the `comments` table references `books(id)` with `ON DELETE CASCADE`, so deleting a book removes its comments.

The app does not run migrations at startup — the tables are expected to already exist.

```bash
# Build the database image
docker build -t bookapi-db ./docker

# Run it (exposes PostgreSQL on :5432)
docker run --name bookapi-db -p 5432:5432 -d bookapi-db
```

The image sets `POSTGRES_USER=pguser`, `POSTGRES_PASSWORD=pgpwd`, and `POSTGRES_DB=bookapi`, matching the default `DATABASE_URL` above.

## Running

With the database running:

```bash
go run .
```

The server listens on `:8080`. Trusted proxies are disabled, so client IPs are taken from the connection rather than forwarding headers. The HTTP server is configured with timeouts (5s read-header, 15s read, 15s write, 60s idle), and on `SIGINT`/`SIGTERM` it shuts down gracefully with a 10 second drain window.

To build a binary instead:

```bash
go build -o bookapi .
./bookapi
```

Gin runs in debug mode by default; set `GIN_MODE=release` to quiet the startup warnings and request logging.

## API

All routes are served under the `/api/v1` prefix.

| Method   | Path                         | Description               | Success response       |
| -------- | ---------------------------- | ------------------------- | ---------------------- |
| `GET`    | `/api/v1/books`              | List all books            | `200` with JSON array  |
| `GET`    | `/api/v1/books/:id`          | Fetch a single book by ID | `200` with the book    |
| `POST`   | `/api/v1/books`              | Create a book             | `201` with the book    |
| `POST`   | `/api/v1/books/:id/comments` | Add a comment to a book   | `201` with the comment |
| `DELETE` | `/api/v1/books/:id`          | Delete a book by ID       | `204` with no body     |

Listing and fetching preload each book's comments. The list endpoint is not paginated.

### Book

```json
{
  "id": 1,
  "title": "The Go Programming Language",
  "author": "Donovan & Kernighan",
  "comments": ["A classic", "Great reference"]
}
```

`id` is generated by PostgreSQL from the `books_id_sequence` sequence; any value sent by the client is ignored. `comments` is exposed on the wire as a flat array of strings, even though each comment is persisted as its own row in the `comments` table. A book with no comments marshals `"comments": null`.

On `POST /api/v1/books`, `title` and `author` are required and must not be blank. A `comments` array may be supplied in the same request; each string is inserted as a comment of the new book.

### Comment

Comments are added via `POST /api/v1/books/:id/comments` with a body of:

```json
{
  "text": "A classic"
}
```

`text` is required and must not be blank. The response is the stored comment, in its own representation (unlike the flat strings nested under a book):

```json
{
  "id": 1,
  "book_id": 1,
  "text": "A classic"
}
```

### Errors

Errors are returned as `{"error": "..."}`:

- `400 Bad Request` — the `:id` path parameter is not a valid unsigned integer, the request body is not valid JSON, or a required field is missing or blank (`title is required`, `author is required`, `text is required`).
- `404 Not Found` — no book exists with the given ID, on `GET /books/:id` and `POST /books/:id/comments`.
- `500 Internal Server Error` — a database/query error occurred. The response body is always the generic `{"error": "internal server error"}`; the underlying error is logged server-side instead of being returned to the client.

`DELETE /api/v1/books/:id` treats an unknown ID as success and still answers `204`.

## Examples

```bash
# Create a book
curl -X POST http://localhost:8080/api/v1/books \
  -H 'Content-Type: application/json' \
  -d '{"title":"The Go Programming Language","author":"Donovan & Kernighan"}'

# Create a book with comments in the same request
curl -X POST http://localhost:8080/api/v1/books \
  -H 'Content-Type: application/json' \
  -d '{"title":"The Practice of Programming","author":"Kernighan & Pike","comments":["Short and sharp"]}'

# List all books
curl http://localhost:8080/api/v1/books

# Fetch one
curl http://localhost:8080/api/v1/books/1

# Add a comment to a book
curl -X POST http://localhost:8080/api/v1/books/1/comments \
  -H 'Content-Type: application/json' \
  -d '{"text":"A classic"}'

# Delete one
curl -X DELETE http://localhost:8080/api/v1/books/1
```

## Layout

```
main.go                  # server setup, DB connection, repository/handler wiring, graceful shutdown
doc.go                   # package documentation for the command
handlers/handlers.go     # HTTP handlers, BookStore interface, route registration
handlers/doc.go          # package documentation
repository/repository.go # Book and Comment GORM models, JSON marshalling, and BookRepository
repository/doc.go        # package documentation
docker/                  # PostgreSQL image (Dockerfile) and schema seed (init.sql)
```

The handlers depend on the `BookStore` interface (`Insert`, `Find`, `FindAll`, `AddComment`, `Delete`) rather than on `*repository.BookRepository` directly, which is what lets the handler tests substitute a mock. Implementations signal a missing book with `gorm.ErrRecordNotFound` so the handlers can answer `404` rather than `500`.

Browse the API docs locally with:

```bash
go doc -all ./...
```

## Testing

Unit tests use [testify](https://github.com/stretchr/testify). Repository tests run against an in-memory SQLite database (auto-migrated from the models), and handler tests use `httptest` with a mocked `BookStore`.

```bash
go test ./...
```
